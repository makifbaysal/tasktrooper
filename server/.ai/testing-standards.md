# Testing standards — server

How every agent writing or maintaining tests in `server/` must verify code. See
[coding-standards.md](coding-standards.md) for the comment and interface rules.

## Command

```sh
go build ./... && go vet ./... && go test ./...
```

`CGO_ENABLED=1` is required (tree-sitter is cgo). Tests that need Postgres start
their own embedded instance (`platform/database.StartEmbedded`) — nothing
external has to be running.

## Mocks are generated, not written

Mock files come from **mockery** via `go generate`, so a new method on an
interface never forces hand-maintenance of a mock. The wiring:

- `internal/port/mocks` is regenerated by `go generate ./internal/port/...`
  (see the `//go:generate mockery` directive and `.mockery.yaml`).
- Never hand-write a `MockFoo` struct. If an interface has no generated mock
  yet, generate it instead of inlining a struct in the test.
- Every mock is used **with expectations**: `mock.On("Foo", args...).Return(...)`
  and `mock.AssertExpectations(t)` at the end (or in the suite's
  `TearDownTest`).

## Structure

- Stateful shared setup (constructing the unit under test, its mocks, the
  in-memory stores) uses `testify/suite`: one `*Suite` per package, `SetupTest`
  per test, `TearDownTest` asserting mock expectations.
- Single behavior with several input/error branches is a **table-driven test**
  (`[]struct{...}` + `Run`/`s.Run`), not copy-pasted test functions.
- A store method whose correctness depends on a CTE's snapshot semantics can
  only be verified against the real engine; write that against Postgres and
  keep the rest at the Go level.
- Database-backed suites share one embedded cluster per test binary, started
  on first use and stopped in `TestMain`: `newTestDatabase` in
  `adapter/storage/postgres` (a migrated clone per suite) and `sharedPostgres`
  in `platform/database` (migration suites create, name and drop their own
  empty databases on it). Never `StartEmbedded` per suite: an initdb, a server
  start and the whole migration history cost ~10 s each time. Keep databases
  and roles rerunnable (`DROP DATABASE IF EXISTS`, create-if-missing) so
  `-count=N` works. Guard with `if testing.Short() { t.Skip(...) }`.
- Tests that only need a seam (a store a service persists through, a tool a loop
  executes) use mockery mocks with expectations; use a small stateful fake only
  when a test's behavior genuinely depends on accumulated state across calls.

## Naming and assertion style

- Test files: `<unit>_test.go`. Test names describe the behavior, not the
  implementation.
- Prefer `assert`/`require` from testify (`s.NoError`, `s.Equal`, ...) over raw
  `if` checks.
- No comments explaining WHAT a test does — the name and assertions say that.
