How many variants a screen gets: when the human names a number — in the description, a comment or the task chat — exactly that many, no more and no fewer. Otherwise two for a new screen or flow, and one for a small change to an existing screen (a field, a section, a state, a copy or layout adjustment). All variants of all screens live in the ONE canvas document `design: <feature>`: each screen is a page, each variant a lettered row on it (`Variant A — table first`, `Variant B — …`), stacked so the human compares them side by side without opening another file. Variants differ in structure — hierarchy, layout, navigation, density — never only in colour; all of them use the same design system. Every variant is complete (both widths, every state). With two or more, one is recommended with its reason, by its screen and variant heading, in the summary comment and as the recommended answer of ONE non-blocking open question (design-variants). A screen's choice is the latest human comment or answer that names one of its variants (`Variant B`; the legacy `Chosen variant: <document title>` marker counts too), else the answered variant question, else its recommended answer; each screen is chosen on its own, and a screen drawn once has nothing to choose. A design system task has no variants: it proposes one design system.
